# Datasets

The framework consumes the **interaction metadata** of an enterprise social
network plus **generalised profile attributes**. It never reads message
content, names or contact details (see the data-access figure in the thesis:
only the shaded categories are consumed).

## Layout

```
data/
├── synthetic/   # demo data generated by `fcf generate-data` (tracked in git)
└── raw/         # place real exports here (git-ignored, never committed)
```

## Tables (one CSV per table, `api_events.csv.gz` may be compressed)

| Table | Columns | Notes |
|---|---|---|
| `users.csv` | `user_id, full_name, username, job_title, department, division, country, airport, terminal, employee_category, shift_pattern, age, preferred_language` | `full_name` / `username` are dropped by the compliance layer; `age`, `country`, `airport`, `terminal` are generalised into bins. |
| `consent.csv` | `user_id, consent, jurisdiction` | Users with `consent = 0` are excluded from every table. |
| `api_events.csv(.gz)` | `event_id, user_id, timestamp, event_type, normalised_path, method, client, object_type, object_id` | The API activity log. Event types: `post.created, comment.created, reaction.created, chat.message.sent, login, stream.viewed, topic.viewed, post.read, search.performed`. `client` is `web` or `mobile`. Paths are normalised (`/posts/{post_id}/comments`). |
| `posts.csv` | `post_id, author_id, stream_id, created_at, has_video, mention_count, comment_count, like_count, comment_like_count` | Metadata only, no payload. |
| `comments.csv` | `comment_id, post_id, author_id, created_at, like_count` | Metadata only. |
| `reactions.csv` | `reaction_id, post_id, user_id, created_at, reaction_type` | |
| `streams.csv` | `stream_id, stream_name, stream_type, restricted` | `stream_type` is `broadcast` or `discussion`. |
| `stream_permissions.csv` | `user_id, stream_id, can_access` | Only restricted streams appear; a stream absent from the table is open to everyone (Algorithm "user permissions"). |
| `group_memberships.csv` | `user_id, group_id, group_name` | |
| `ground_truth_archetypes.csv` | `user_id, archetype, archetype_name` | Synthetic data only: the latent archetype each user was drawn from, used to validate the pipeline. Not an input. |

## Synthetic data

`data/synthetic/` is produced by

```bash
fcf generate-data --out data/synthetic --n-users 400 --days 42 --seed 7
```

Users are drawn from four latent archetypes whose monthly activity rates
mirror Table "Average behavioural feature values per cluster" of the thesis
(high communicators, reactive consumers, operational browsers, low-engagement
users). Timestamps follow each user's shift pattern (`office`, `day`,
`night`, `short`, `long`, `split`) and the archetype's working-hours share.
Posts, comments and reactions are derived from the event log, so aggregates
are consistent across tables. Names are fabricated from short word lists.

Any other dataset with the same column layout can be used by pointing
`data.root` (or `fcf run --data-root`) to its directory.

## Legacy per-user count exports

Older exports that ship a serialised `event_type_counts` column can be
expanded with `fcf unpack-events <file.csv>`; the resulting numeric columns
can then be mapped to indicators in a custom configuration.
